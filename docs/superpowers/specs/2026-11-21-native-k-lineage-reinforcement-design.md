# Native NEW K source-lineage reinforcement — design

## Intent

Keep the active Deagle V.A. Proof Estate anchored to corrected NEW K / URK, without allowing a later public reference implementation to be silently presented as the native substrate. Preserve unchanged historical mathematics and original records.

## Evidence and boundaries

- The local Library R19 national-cyber archive contains six Python files with exactly the same Git blob SHA-1 identities as the corresponding public `Kamanaka5502/national-cyber-boundary` files (examined 2026-11-21). Byte identity establishes shared code, **not** who copied it, when, or under what license.
- R19 is a one-corridor visible example; neither its existing test suite nor its reported outcomes establish native V12 execution or eight-corridor coverage.
- The current Deagle hub already labels corrected NEW K as operative, and its archived 39 Kamanaka repository references are not published as native implementation.
- No protected kernel, customer data, or R19 code enters the public Git repository. Do not edit archived research mathematics or history.

## Approach

Add an automated **source-lineage guard** to the hub's existing CI. It checks current foundation identity, forbids exact-byte reintroduction of the six known reference modules anywhere in active source, and retains all 36 mapped source references as non-native references. Add adversarial negative controls and a bounded public provenance record.

## Alternatives considered

- Replacing public files with proprietary/new native math: rejected—no authorized, release-cleared original executable carrier is in this public repository.
- Globally replacing `old K` text: rejected—would corrupt unchanged historical research and evidence.
- **Chosen:** fail-closed source-lineage verification without modifying protected content.

## Acceptance

1. Current foundation and source inventory validate.
2. A deliberate old-K substitution in an active hub page is rejected.
3. A deliberate byte-matched reference module is rejected.
4. Historical math content is untouched.
5. CI runs the new gate and its adversarial tests; no native success is claimed.
