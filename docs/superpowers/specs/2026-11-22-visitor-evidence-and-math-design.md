# Teacher — Visitor Evidence and Mathematics Answers

## Intent and authority

Terry wants the public Teacher to answer real first-visitor questions, not substitute a generic lesson for the question. The public Natural Order knowledge is offered to everyone. A visitor asking for independent evidence should receive the published pilot, document, repository and review routes together with a plain-language explanation. A mathematical question should receive the relevant indexed result/status, current work path, or a candid statement that no public answer was located, plus an optional human inquiry route.

## Approaches

- **Selected:** add a small, finite, source-bound Visitor Answer Desk before existing keyword routing. It admits explicit compliance/custody, independent proof/pilot, and named mathematical inquiries; it never invents a solved theorem. This fixes the demonstrated first-visitor failures while preserving eleven existing teaching kernels.
- **Merely add more keywords to generic lessons:** rejected because the relevant sources and answer scope still would not match the question.
- **Introduce a general solver or unreviewed network search:** rejected because the public Teacher is currently static and offline; no authorized native mathematical solver or remote research runtime is included.

## Visitor behavior

1. **Compliance and underwriting:** explain human-supervised compliance versus V.A.'s claimed native consequence-custody architecture before power, with the custody system itself as the system offered for underwriting. Distinguish engineering aim and bounded published evidence from insurer acceptance.
2. **Independent proof:** identify the evidence hall, public pilots, historical index, original review standard, and repository route. A link or receipt alone does not establish independent real-world reproduction; explain the required observation, changed-condition control, bypass challenge, and replay.
3. **Mathematics:** link the public mathematics index, research publication status, ongoing research and appropriate named records. Specifically answer P versus NP as bounded public examination without an unrestricted resolution; give scoped status for Navier–Stokes, Yang–Mills, RH and Erdős–Straus when asked. An unfamiliar math question receives an honest "not located in this public index" response, not an invented theorem.
4. **Request an answer:** show an optional email-draft link only in the mathematics answer context, using the visitor's own question. Nothing is sent or stored automatically, and visitors are reminded to omit sensitive information.
5. **Privacy and corrections:** full-turn protected-access checks precede public answers. An overt correction, open conversation and previous lesson continuity remain intact; a new question overrides stale context.

## Public-scope constraints

- Preserve eleven subject teaching kernels, disabled Frankie client, static CSP, no runtime network or local storage.
- No protected mathematical construction, owner-only record, or secret in public source.
- Do not claim all mathematics has been resolved, all pilots independently replicated, or insurer underwriting approved merely because a route exists.
- Published source links must be real, public, safe, and release-audited.

## Acceptance

- The three previously failing LinkedIn-like prompts return direct, specific, source-linked answers.
- Named mathematical status is bounded; unknown mathematics invites further public examination/contact without pretending a negative global result.
- Explicit private mathematical request remains access-only, even if it mentions public evidence or P versus NP.
- Selecting a source does not send a learner question; email requires a separate, visible visitor action.
- Full public suite and privacy audit pass; site deploys with the updated versioned module graph.
